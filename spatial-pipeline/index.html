Engine eronder · multi-source · soeverein

Geometrie scheiden van attributen — zodat de bril 10× groter gebied kan laden

Een Nederlands overheids-VR-platform laadt nu OBJ + JSON tegelijk in de bril. Daardoor zit een vergaderzaal vast aan kleine gebieden. Deze pipeline scheidt geometrie (glTF, geometry-only met BAG-id per pand) van attributen (JSON-LD linked-data, opvraagbaar als iemand op een pand klikt) — meer panden, meer plannen, meer aanduidingen tegelijk in beeld.

Het knelpunt nu

VR-applicaties laden geometrie + attributen samen — dat schaalt niet. Vergaderzalen zitten vast aan kleine gebieden; grotere areas zijn niet beleefbaar zonder de bril te overstelpen.

Wat deze pipeline doet

Drop tile + meerdere IMRO-plannen → join in browser → glTF (alleen geometrie + IDs) + JSON-LD (linked-data attributen, opvraagbaar via ID). Klaar voor Unity-pickup. Geen vendor lock-in, swappable van Azure naar EZ naar on-prem.

1Drop3D BAG-tile + IMRO-plannen (heterogene bronnen — IMRO2008 + IMRO2012)
2Joinelk pand → primaire bestemming + alle dubbelbestemming-overlays + provenance per regel
3Klikbewijst dat attributen on-demand opvraagbaar zijn via gebouw-id
4Exporteermodel.glb (geometrie, ~MB) + attributes.jsonld (linked-data, ~KB) — Unity-pickup-ready

Alle geometrie- en plan-verwerking gebeurt client-side — verifieerbaar via Network-tab. Eén live attribuut-fetch naar publieke Luchtmeetnet open API (RIVM, CC0, geen auth, geen tracking) toont de engine-eronder-architectuur. Open-source vendored deps (three.js MIT, turf MIT, earcut ISC). Application-code PolyForm-NC. Uitwisselbaar tussen Azure / EZ / Nextcloud / on-prem.
